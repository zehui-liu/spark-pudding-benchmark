Notes:

- E2E-04 includes the full 10M bootstrap and the incremental 2-insert/1-update
  run; wall time covers both Spark applications.
- E2E-06 was stopped by the runner's 4800 s timeout after the snapshot had
  completed and the job had been streaming idle. The data completion time is
  derived from the last Hudi commit: job start `20:36:44`, last commit
  `21:27:21`, i.e. `3037 s`. The row count was verified separately with
  `table-check.sh hudi ... --count 10000013`; the runner's `cp` path bug made
  the wrapper exit 1 after the job itself succeeded.
- A stale inactive PostgreSQL replication slot had retained 8.6 GiB of WAL and
  caused the first E2E-04 attempt to fail with `No space left on device`. The
  slot was dropped; the successful run used the same target/source data.
- E2E-06 first hit `max_wal_size`/disk pressure only in PostgreSQL, which is not
  used by that case; the run itself used MySQL and the host filesystem.
- E2E-09's producer and streaming job finished writing by Hudi commit
  `20261112000720160`; the job then idled until it was stopped. The effective
  completion is measured from the first Hudi commit, not from the idle wait.
- E2E-14 Hudi/Paimon scale templates were added for this baseline. Both created
  a new 10M-row table; they did not replace an existing 200-row table like the
  Iceberg scale case.
- E2E-06 Iceberg scale required a pre-created Iceberg table
  (`create-iceberg-table.sh`) and a continuous trigger; the streaming sink
  rejects `available-now` for an unbounded MySQL CDC source. It was stopped as
  soon as the Iceberg `total-records` reached 10,000,013, so its 1021 s wall
  time is the data-completion time, not an idle timeout.
