# Component and E2E job templates

English | [简体中文](README.zh-CN.md)

The 34 component templates (`SR-*`, `SK-*`, `TR-*`) are generated by
[`scripts/run/generate_jobs.py`](../../scripts/run/generate_jobs.py). Do not edit a
generated file by hand; edit the generator and re-run it.

```shell
python3 scripts/run/generate_jobs.py
```

E2E templates (`E2E-*`) are handwritten because they need multi-run state, except
the seven `E2E-14-*-full-refresh` variants, which are generated by
[`scripts/run/generate_e2e14_jobs.py`](../../scripts/run/generate_e2e14_jobs.py).

## Placeholders

`scripts/run/run-case.sh` renders these with `envsubst` per case:

| Placeholder | Meaning |
| --- | --- |
| `${SPARK_HOME}` | Spark installation |
| `${PUDDING_HOME}` | unpacked spark-pudding distribution |
| `${PUDDING_TEST_ROOT}` | this testbed root |
| `${PUDDING_TEST_DATA}` | `data/seed` (smoke) or `data/generated` (scale) |
| `${CASE_OUT}` | `results/runs/<case>/output` |
| `${PG_URL}`, `${PG_USER}`, `${PG_PASSWORD}` | PostgreSQL source |
| `${PG_TARGET_URL}` | PostgreSQL target database (`target_db`) |
| `${MYSQL_URL}`, `${MYSQL_USER}`, `${MYSQL_PASSWORD}` | MySQL source |
| `${MYSQL_TARGET_URL}` | MySQL target database (`target_db`) |
| `${MONGO_URI}` | MongoDB replica-set URI |
| `${KAFKA_BOOTSTRAP}` | Kafka bootstrap servers |
| `${ES_PORT}` | Elasticsearch HTTP port |

## Cases

| Range | Count | Notes |
| --- | --- | --- |
| `SR-01` … `SR-13` | 13 source types | `SR-11` … `SR-13` are streaming-only CDC templates |
| `SK-01` … `SK-11` | 11 sink types | `SK-08` must run before `SR-07` to create the Hive table |
| `TR-01` … `TR-10` | 10 transforms | file source → transform → file sink |
| `E2E-01`, `E2E-04`, `E2E-05`, `E2E-09` | 4 end-to-end paths | run through `scripts/run/run-e2e.sh` |
| `E2E-14-*-full-refresh` | 7 sinks | `sync full`; run twice with `E2E14_LIMIT=100` then `200` |

The first ten source templates and all sink/transform templates are finite batch
jobs. CDC templates use a processing-time trigger and are stopped by the runner
with `--allow-timeout`.

Component CDC templates use a file sink so the runner can assert the decoded
`__op`/`_cdc_sequence` rows without starting another Spark job. Sink behavior for
Paimon/Iceberg/Hudi is covered by `SK-*` and by the E2E cases.

## Prerequisites

- `SR-04` and `SR-13` need a 10,000-document `source_db.orders_smoke` collection:
  `scripts/run/prepare-mongo-smoke.sh`.
- `SR-12`, `E2E-04` need a 10,000-row PostgreSQL `source_db.orders_smoke` table:
  `scripts/run/prepare-postgres-smoke.sh`.
- `E2E-05` needs a 10,000-row MySQL `source_db.orders_smoke` table:
  `scripts/run/prepare-mysql-smoke.sh`.
- `SR-06` and `E2E-09` need the `orders-smoke` topic:
  `scripts/run/prepare-kafka-smoke.sh`.
- `E2E-05` / `E2E-09` need their target tables pre-created because streaming
  lakehouse CDC/upsert requires an existing table:
  `scripts/run/create-paimon-table.sh` and `scripts/run/create-hudi-table.sh`
  (both called by `run-e2e.sh`).
- `SR-07` needs the Hive table created by `SK-08`.
- `SR-02`/`SR-03` need the PostgreSQL/MySQL JDBC drivers on the Spark classpath;
  the testbed currently installs `postgresql-42.7.3.jar` and
  `mysql-connector-java-8.0.30.jar` into `$SPARK_HOME/jars`.
- Lakehouse source cases read the 1 GiB baseline tables under
  `data/generated/lakehouse`.

## E2E state

Multi-run cases keep state outside `results/runs/` so rerunning the case is safe:

| Case | Durable state | Target |
| --- | --- | --- |
| `E2E-04` | `results/state/e2e-04` | `target_db.e2e04_orders` |
| `E2E-05` | `results/state/e2e-05/checkpoint` | Paimon `pudding_test.db/e2e05_orders` |
| `E2E-09` | `results/state/e2e-09/{checkpoint,hudi/orders}` | Hudi `e2e09_orders` |
| `E2E-14` | `results/state/e2e-14` | file/Hive/JDBC/MySQL/Hudi/Paimon/Iceberg |

`run-e2e.sh` resets those paths and the smoke source tables before the first run.
